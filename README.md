# PTH · 生产岗位培训与工序交接

**PTH = Production Training & Handover**，一个用于演示生产岗位培训与工序交接闭环的独立项目。

这是依据[需求文档](docs/生产岗位培训与工序交接业务分析/requirements.md)制作的演示项目，用三份合成记录演示资料核对、问题处理、业务变更确认、质量复核、接收和归档。仓库包含可运行页面、业务规则、自动化测试、业务文档与流程图。

本版使用确定性规则和浏览器本地保存。它没有连接大语言模型、企业数据源、真实账号或审批系统。页面中的角色、人员、来源和确认记录均用于演练；规则输出不是一次真实 AI 调用，演示确认不具有正式业务效力。

## 快速启动

使用 **Node.js 20 或更高版本**及随附的 `npm`。这是本项目采用的运行与测试版本下限：测试使用内置 `node:test`，业务模型使用 `structuredClone` 和 `Array.prototype.findLast`。本次实际验证版本为 Node.js `24.18.0`，其他版本尚未逐一验证。

克隆公开仓库并进入项目目录；也可以从 **Code** 按钮下载源码 ZIP 后解压：

```bash
git clone https://github.com/ETEZ-AI/PTH.git
cd PTH
npm start
```

项目没有第三方 npm 依赖，**无需执行 `npm install` 或前端构建**；服务器直接提供 `dist/` 中的页面。浏览器需支持 ES modules、`structuredClone`、`Array.prototype.findLast` 和 `localStorage`。

打开 [本地演示](http://127.0.0.1:4186)。服务仅监听本机 `127.0.0.1`；关闭时在启动终端按 `Ctrl+C`。上传源码至 GitHub 不会自动发布可在线访问的应用。

默认端口为 `4186`，已使用 `npm start` 启动并重新打开浏览器验证。若该端口已被占用，可以指定其他可用端口，例如：

```bash
node server.mjs --port 4187
```

使用上述示例时打开 `http://127.0.0.1:4187`；`4187` 仅为备用端口示例，本次未运行。实际浏览器验收均在 `4186` 完成。不要直接双击 `dist/index.html`，以免浏览器模块加载和本地保存行为与 HTTP 运行方式不同。

## 演示角色

| 角色 | 标识 | 演示职责 |
| --- | --- | --- |
| 现场专员 | `site` | 准备、修正资料，核对并提交交接包 |
| 交付协调员 | `coordinator` | 建立任务、跟踪交接和执行归档检查 |
| 业务负责人 | `owner` | 确认指引、培训依据等资料变更，以及提交后重新修订的记录 |
| 质量复核人员 | `quality` | 对当前修订通过、退回或标记待核查 |
| 接收人员 | `receiver` | 接受交接或带原因退回 |

角色切换用于在同一浏览器内演示不同职责。它不是登录、身份认证或权限安全控制，也不能证明具备跨企业数据隔离能力。

初始样本均属于合成批次 `B-20261012`、岗位 `PK-01`、工序 `PK-07`：

| 编号 | 样本 | 初始状态 |
| --- | --- | --- |
| `HJ-001` | 夜班包装交接 · 旧版清单待核对 | 草稿；引用 v1、培训待确认，存在封签复核未结项 |
| `HJ-002` | 日班包装交接 · 完整资料样本 | 草稿；v2 依据和字段核对齐备 |
| `HJ-003` | 中班包装交接 · 待质量复核 | r1 已提交，可演示质量通过、退回或待核查 |

## 演示路径

操作前可用页面的重置入口恢复三份合成样本。重置会清除当前演示进度；需要保留时先导出证据。按详情页的当前状态和待办提示办理，不跳过规则阻塞项或人工确认。

### 1. 正常交接到归档

1. 选择 `HJ-002 日班包装交接 · 完整资料样本`，切换为现场专员。
2. 查看岗位、工序、业务发生时间、指引及培训记录，并打开对应来源。执行规则核对，检查清单中的缺失、未确认、冲突或读取问题。
3. 完成当班字段核对并提交当前修订。若还有阻塞项，先按清单补齐，再重新核对；提交本身不等于质量通过。
4. 切换为质量复核人员，核实来源和当前修订，填写必要依据后通过质量复核。
5. 切换为接收人员，检查同一修订的交接内容并接受。
6. 切换为交付协调员，执行归档。归档应检查当前修订的必要确认与问题处理情况，详情及时间线可回查办理经过。
7. 导出 JSON 证据包，检查记录、来源、修订、确认和审计是否对应。归档仅表示演示中的交接记录闭环，不代表安全培训合格、可操作设备或生产放行。

也可由协调员新建任务，填写页面要求的批次、岗位、工序、班次、接收人员、发生时间和期限。演示资料仅支持岗位 `PK-01`、工序 `PK-07`，接收人为演示接收人员，期限不得早于发生时间。新任务的指引和培训依据最初为空，补齐后仍需规则核对与必要的业务变更确认。新建任务不会向企业系统分派真实工作。

### 2. 夜班旧清单、问题处理与重新确认

1. 选择 `HJ-001 夜班包装交接 · 旧版清单待核对`，以现场专员身份执行规则核对。
2. 打开发现项的来源，区分指引差异、培训依据不足与仅缺少确认；不能直接把旧版本号等同于历史培训失效。
3. 打开合成 v2 指引与补充培训来源，将交接指引、培训依据均改为 `v2`，确认培训记录和当班关键字段，填写变更原因后保存。处理“封签复核新增项未留存确认”，填写明确处理说明，例如“已对照合成 v2 指引核对封签复核项，补充培训与当班检查记录待质量复核”。处理说明不应替代仍然缺失的事实或来源。
4. 重新执行规则核对；无阻塞项后提交。该记录改过指引和培训依据，将进入业务变更确认。
5. 切换为业务负责人，确认当前修订。随后切回现场专员，**重新核对并再次提交**；负责人确认本身不直接进入接收或归档。
6. 由质量复核人员通过当前修订，再由接收人员接受、协调员归档。

已提交记录的修订失效路径可用 `HJ-003` 演示：先由质量通过 r1，再由现场修改资料并保存新修订，检查原质量确认已失效；负责人确认后重新核对、提交、复核和接收。旧确认应保留在历史中，不能用于新版归档。

退回分支可以在质量复核或接收环节演示：填写退回原因，返回现场修正，再重新走当前修订所需的确认。选择“待核查”应保留问题与原因，而不是形成通过结论。

### 3. 来源读取失败与恢复

1. 切换为交付协调员，选择一份未归档记录，使用来源读取失败的演示控制。该控制影响所有未归档任务，并非只影响选中的记录。
2. 查看历史来源、快照时间和失败提示。旧快照仍可用于追溯，但不能显示为已读取最新资料，关键问题不能默认通过。
3. 使用来源恢复的演示控制，重新执行规则核对，再按当前待办继续办理。恢复来源本身不应自动产生质量或接收确认。
4. 检查审计和导出记录，确认失败、恢复、重新核对及后续人工操作有迹可循。已归档记录继续保留原归档信息。

这些控制只切换合成资料状态，没有实际断开或恢复企业接口。

目标流程可查看 [SVG 大图](dist/assets/overall-flow.svg) 或用 BPMN 编辑器打开[目标流程文件](dist/assets/overall-flow.bpmn)。它们说明辅助工作台目标流程；其中设计内容是否已实现，以当前演示和验收记录为准。

## 保存、导出与重置

- 草稿和演示进度保存在当前浏览器的 `localStorage`，使用键 `handover-evidence-demo.v1`；同一浏览器、同一 origin 刷新后读取本地记录。origin 包括协议、主机名和端口；`localhost` 与 `127.0.0.1`、`4186` 与 `4187` 都是不同的保存空间。跨 origin 差异尚未专门实测。
- 停止本地服务不会删除浏览器记录。其他浏览器、其他设备和不同 origin 不会自动共享进度；无痕窗口或清理网站数据可能丢失记录。
- 本版没有服务端数据存储、真实多人协作、企业备份或正式审批回执接入。不要用多个标签页的角色切换来代替并发安全或权限验收。
- JSON 导出用于查看和留存合成证据，不代表已实现备份恢复或导入能力。文件中的演示身份与确认不能作为真实业务凭证。
- 页面重置入口仅用于清除本演示进度并恢复样本。保留需要的导出后再重置，不需要清除整个浏览器的所有网站数据。
- 本演示不需要真实人员资料、账号口令或企业原件。真实资料进入前仍需落实需求文档中的身份授权、来源接入、数据留存和业务确认条件。

## 本版边界

当前规则和来源只覆盖合成包装岗位 `PK-01`、工序 `PK-07` 及预设的 `v1`／`v2` 关系。它们用于验证办理过程，不是通用的培训覆盖判定或企业有效版本规则。

| 本地演示可观察的内容 | 不能据此声称完成的能力 |
| --- | --- |
| 合成任务、规则核对、问题处理与角色操作 | 真实资料抽取、真实 AI 推理、企业系统接入 |
| 浏览器中的角色与状态转换检查 | 服务端认证、对象权限、多租户隔离、防篡改审计 |
| 本地修订、模拟确认、接收及归档 | 企业正式审批、培训资格认定、实际责任转移 |
| 合成来源失败与恢复、JSON 证据导出 | 企业连接器运维、生产故障恢复、备份恢复承诺 |
| 本地保存与演示测试 | 多人并发正确性、生产容量、SLA、真实业务验收 |

需求中的 50 次交接、四周试点和业务骨干投入属于待真实项目确认的演练口径。三份合成记录跑通不代表 50 次样本验收通过，也不能证明节约了真实工时。

## 项目目录

- `dist/`：应用页面、交互、业务状态机和目标 BPMN。
- `tests/`：业务规则与闭环测试。
- `docs/`：需求文档、业务分析、访谈来源及传统流程图。
- `diagram-source/`：目标 BPMN 的生成脚本与结构校验结果。
- `qa/`：浏览器截图、验收记录与文件校验值。
- `server.mjs`：仅监听本机的静态文件服务器。
- `package.json`：启动、测试与语法检查命令，无第三方 npm 依赖。

如另行收到 `PTH-demo.zip` 本地交付包，解压后进入其中的 `PTH/` 运行 `npm start`。ZIP 文件不纳入 Git 仓库；从 GitHub 克隆或下载仓库源码即可运行。
